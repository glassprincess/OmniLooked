# OmniView — Этапы 1–2

Клиентский просмотрщик файлов: всё читается локально в браузере, ничего не отправляется на сервер.
Этап 1: каркас (контракт плагина, диспетчер жизненного цикла, FileSniffer, динамические импорты),
MediaViewer, CodeViewer и Universal Fallback (Smart Text / Strings / Hex).
Этап 2: DocViewer (HTML/SVG/Markdown), OfficeViewer (OOXML + ODF + legacy), ArchiveViewer (ZIP),
PDFViewer (pdf.js: canvas + текстовый слой).

## Запуск

Версии зависимостей в `package.json` намеренно не указаны: `pnpm add` запишет актуальные.

```sh
pnpm add -D vite typescript
pnpm add jschardet
pnpm dev            # разработка
pnpm build          # tsc --noEmit && vite build
pnpm check:size     # размер стартового бандла (gzip и brotli), лимит 100 КБ применяется к gzip
pnpm preview
```

`vite.config.ts` использует `base: './'`, поэтому `dist/` работает из любого подкаталога (GitHub Pages) без правок.

## Структура

```
src/core/       sniffer, signatures, encoding, registry (реестр ленивых модулей), dispatcher (жизненный цикл)
src/viewers/    media/ (картинки zoom/pan, audio, video), code.ts, doc/ (HTML/SVG/Markdown: Preview + Source),
                office/ (OOXML: docx/xlsx/pptx; ODF: odt/ods/odp; legacy: doc/xls через свои CFB/FIB/BIFF-парсеры),
                archive/ (ZIP: список + открытие внутрь), pdf/ (pdf.js: canvas + текстовый слой),
                fallback/ (Text, Strings в Worker, Hex)
src/ui/         app (Empty/Loading/Viewer/Error, история вложенных файлов), VirtualList, theme, dom, icons
src/i18n.ts     EN по умолчанию, RU по navigator.language
```

## Принятые решения (можно оспорить)

- Читаемость текста: файлы > 8 МиБ (`TEXT_PREVIEW_MAX_BYTES`) показываются усечённо с уведомлением. Hex и Strings работают со всем файлом порциями.
- `.html`, `.svg`, `.md`/`.markdown` открываются в DocViewer с двумя вкладками «Просмотр» / «Исходник». HTML и Markdown рендерятся в `<iframe sandbox="allow-popups allow-popups-to-escape-sandbox">` (скрипты, формы и same-origin заблокированы), SVG — через `<img>` (там скрипты не выполняются). Markdown парсится своим мини-рендером без зависимостей (escape-first, картинки не грузятся — только плейсхолдер со ссылкой).
- `.docx`/`.xlsx`/`.pptx` открываются в OfficeViewer: ZIP распаковывается локально (`fflate`, ленивый чанк), XML парсится `DOMParser`, весь текст вставляется только через `textContent` (XSS невозможен), картинки — через blob-URL в `<img>`. Слайды читаются из любых контейнеров (`sp`, `grpSp`, `AlternateContent`, `cxnSp`), таблицы — из `graphicFrame`, текст SmartArt/диаграмм извлекается. Упрощения: слайды — стопкой карточек без точного дизайна, сами диаграммы — плейсхолдер, EMF/WMF не рендерятся, листы обрезаются до 2000 строк / 50 колонок с уведомлением.
- `.odt`/`.ods`/`.odp` — нативный ODF-рендер (тот же ZIP+XML подход): текст со стилями/списками/таблицами, листы с переключателем, слайды карточками.
- Legacy `.doc` — собственный парсер (CFB + FIB + piece table по MS-DOC, сверено с `word-extractor` на реальных файлах): извлекается текст с разбивкой на абзацы, коды полей вырезаются. `.xls` — собственный BIFF8-ридер (CFB + SST/числа/RK/формулы/даты, сверено с `xlrd`): листы как таблицы. Старые Word 6.0/95 и BIFF2–5 не поддерживаются (идут в умный Fallback), файлы legacy-форматов с паролем (RC4) — экран ошибки.
- `.zip` открывается в ArchiveViewer: список файлов с размерами, открытие файла внутрь (кнопка «Назад» возвращает в архив), скачивание отдельных файлов. Шифрованные/битые архивы — экран ошибки.
- Fallback стал умным: бинарные файлы по умолчанию открываются на вкладке Strings (а не мусорным текстом) с уведомлением.
- Legacy `.ppt` — извлечение текста (CFB + TextChars/TextBytes по MS-PPT).
- Пароли больше не тупик: PDF показывает форму ввода пароля прямо во вьювере, шифрованный OOXML (Agile AES-256) расшифровывается локально через WebCrypto + свой AES (проверено векторами FIPS-197 и round-trip с побайтовым сравнением). Неподдерживаемое шифрование и неверный пароль — понятные сообщения.
- `.pdf` — pdf.js в воркере (ленивые чанки ~1.7 МБ всего): постраничный canvas + текстовый слой для выделения, zoom и fit-to-width, пароль спрашивается формой прямо во вьювере. Стандартные шрифты и CMap подтягиваются из `public/pdfjs` по требованию.
- При сбое специализированного просмотрщика показывается экран ошибки с кнопкой «Открыть как текст / Hex-дамп» (без автопереключения).
- `magicBytes` в `matches()` — первые 4096 байт файла (нужны для текстовой эвристики); сигнатуры сверяются по префиксу. Сам интерфейс `FileViewerPlugin` не менялся.
- Виртуальный список ограничивает высоту прокрутки (10 000 000 px) и пропорционально отображает позицию на строки, поэтому Hex огромных файлов прокручивается, но точность колеса мыши на таких файлах грубее.
- Копирование выделения работает только для видимых строк (виртуализация).
- Тема хранится в `localStorage` (ключ `omniview:theme`) только после ручного переключения.

## Ограничения этапа

Не входит в Этап 2 (по roadmap): архивы кроме ZIP (RAR/7Z/…), Word 6.0/95 и BIFF2–5,
старое RC4-шифрование Office (только Agile AES-256), 3D, PSD, EPUB,
service worker и `file_handlers` в манифесте (Этап 4).
Иконка манифеста — SVG; PNG-иконки 192/512 для установки PWA добавляются вместе с service worker.
